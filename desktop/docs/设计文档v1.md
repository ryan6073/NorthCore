# AgentHub PC 端设计文档

## 1. 文档说明

本文档用于说明 AgentHub PC 端的功能设计和 UI 设计。

当前 PC 端采用 Electron 技术方案。PC 端不是重新开发一套独立产品，而是在 Web 端 IM 多 Agent 协作体验基础上，通过 Electron 增强本地系统能力，包括本地文件访问、系统通知、系统托盘、本地 Agent 进程管理和本地命令调用能力。

AgentHub PC 端的目标是让平台从浏览器中的多 Agent 聊天应用，升级为可以连接本地项目、本地文件和本地开发环境的桌面 Agent 工作台。

***

## 2. PC 端产品定位

AgentHub PC 端是一个面向本地开发场景的多 Agent 协作桌面应用。

用户可以在 PC 端中选择本地项目目录，与 Claude Code、Codex、OpenCode、Local Qwen、ReviewAgent、DocAgent 等 Agent 进行单聊或群聊协作。Agent 生成的代码、文档、HTML 页面等 Artifact 可以在应用内预览，也可以在用户确认后写入本地项目文件。

PC 端重点解决的问题是：

1. Web 端无法直接访问本地文件。
2. Web 端无法可靠管理本地 Agent 进程。
3. Web 端系统通知和后台运行能力有限。
4. Agent 生成的代码需要更方便地落地到本地项目。
5. 用户希望在一个桌面工作台中完成聊天、生成、预览、应用和管理。

***

## 3. 技术方案

### 3.1 技术栈

PC 端采用：

React + TypeScript + Tailwind CSS + Electron

其中：

1. React 负责界面渲染。
2. TypeScript 负责类型约束。
3. Tailwind CSS 负责 UI 样式。
4. Electron 负责桌面端能力。
5. Electron Main Process 负责窗口、菜单、托盘、文件系统、系统通知和进程管理。
6. Electron Renderer Process 负责展示 AgentHub 前端页面。
7. Electron Preload 负责在安全边界内暴露本地能力给前端。

***

## 4. Electron 架构设计

### 4.1 进程划分

AgentHub PC 端采用 Electron 标准进程模型：

Main Process\
负责桌面应用的系统级能力。

Renderer Process\
运行 React 前端页面。

Preload Script\
作为 Main 和 Renderer 之间的安全桥梁。

IPC\
负责 Renderer 和 Main 之间的通信。

### 4.2 Main Process 职责

Main Process 负责：

1. 创建应用窗口。
2. 管理窗口生命周期。
3. 创建系统托盘。
4. 创建应用菜单。
5. 调用本地文件系统。
6. 触发系统通知。
7. 打开系统文件夹。
8. 启动和停止本地 Agent 进程。
9. 监听本地 Agent 进程状态。
10. 向 Renderer 返回执行结果。

### 4.3 Renderer Process 职责

Renderer Process 负责：

1. 会话列表 UI。
2. Agent 联系人 UI。
3. 聊天窗口 UI。
4. Artifact 面板 UI。
5. 文件树 UI。
6. 工作区管理 UI。
7. 设置中心 UI。
8. 调用 preload 暴露的 desktop API。
9. 调用后端 HTTP / WebSocket API。

### 4.4 Preload 职责

Preload 负责通过 contextBridge 向前端暴露受控 API。

前端不能直接使用 Node.js 的 fs、path、child\_process 等模块。

前端只能调用 preload 暴露的安全方法，例如：

1. selectDirectory
2. readTextFile
3. writeTextFile
4. showNotification
5. openPath
6. startLocalAgent
7. stopLocalAgent
8. getLocalAgentStatus

### 4.5 安全原则

Electron PC 端必须遵守以下安全原则：

1. Renderer 不直接开启 nodeIntegration。
2. Renderer 不直接访问 Node.js API。
3. 使用 preload + contextBridge 暴露有限能力。
4. 本地文件读取必须基于用户选择的工作区。
5. 写入文件前必须二次确认。
6. 执行本地命令前必须展示命令内容并要求用户确认。
7. API Key 不在界面中明文展示。
8. 本地 Agent 进程管理必须有明确状态和日志提示。

## 6. Platform Adapter 设计

为保持 Web 端和 PC 端统一，前端业务组件不应该直接判断是否是 Electron，而是通过 Platform Adapter 调用平台能力。

### 6.1 PlatformAdapter 能力

PlatformAdapter 应包含：

1. platform
2. getCapabilities
3. pickDirectory
4. pickFile
5. readTextFile
6. writeTextFile
7. showNotification
8. openExternal
9. openPath
10. startLocalAgent
11. stopLocalAgent
12. getLocalAgentStatus

### 6.2 Web 端 Adapter

Web 端不支持本地文件任意读写。

如果用户在 Web 端点击本地文件能力，应给出提示：

当前功能仅在 PC 端可用。

### 6.3 Electron Adapter

Electron Adapter 通过 preload 暴露的 window\.desktopAPI 调用本地能力。

例如：

用户点击选择目录\
↓\
Renderer 调用 platform.pickDirectory\
↓\
preload 调用 ipcRenderer.invoke\
↓\
main process 打开系统目录选择器\
↓\
返回目录路径给 Renderer

## 7. 功能设计

## 7.1 工作区管理

### 功能说明

工作区表示用户当前绑定的本地项目目录。

例如：

D:/Code/NorthCore\
D:/Code/AgentHub\
/home/user/projects/agenthub

### 核心功能

1. 选择本地项目目录。
2. 显示当前工作区路径。
3. 切换最近工作区。
4. 移除工作区记录。
5. 检测工作区是否可访问。
6. 显示工作区状态。
7. 将工作区与会话关联。

### 工作区状态

工作区状态包括：

1. none：未选择工作区。
2. loading：正在加载。
3. active：当前可用。
4. unavailable：路径不存在或无权限。
5. error：读取失败。

### 交互流程

用户点击“打开本地项目”\
↓\
Electron 弹出目录选择框\
↓\
用户选择项目目录\
↓\
Main Process 返回目录路径\
↓\
Renderer 保存当前 workspace 状态\
↓\
文件树刷新\
↓\
标题栏显示当前工作区

***

## 7.2 本地文件管理

### 功能说明

本地文件管理用于展示和访问当前工作区中的文件。

### 核心功能

1. 显示项目文件树。
2. 支持文件夹展开和收起。
3. 支持搜索文件。
4. 支持点击文件预览。
5. 支持将文件加入当前会话上下文。
6. 支持复制文件路径。
7. 支持在系统文件夹中打开。
8. 支持设置 Artifact 保存目标。

### 文件过滤规则

默认忽略以下目录：

1. node\_modules
2. dist
3. build
4. .git
5. .next
6. .vite
7. coverage

### 文件预览类型

第一阶段支持文本类文件：

1. ts
2. tsx
3. js
4. jsx
5. json
6. md
7. html
8. css
9. txt

### 安全规则

1. 只能读取用户主动选择的工作区。
2. 不扫描整个磁盘。
3. 不读取工作区之外的文件。
4. 大文件需要限制大小。
5. 读取失败时需要显示错误提示。

***

## 7.3 Artifact 应用到本地

### 功能说明

Artifact 是 Agent 生成的产物，例如代码、Markdown 文档、HTML 页面、Diff 或部署状态。

PC 端需要支持用户将 Artifact 写入本地项目。

### 核心功能

1. 展示 Artifact 列表。
2. 展示 Artifact 详情。
3. 选择保存路径。
4. 写入本地文件。
5. 覆盖前确认。
6. 冲突时提示。
7. 写入成功后显示系统消息。
8. 写入成功后触发系统通知。
9. 记录 Artifact 应用状态。

### Artifact 写入流程

Agent 生成 Artifact\
↓\
右侧 Artifact 面板展示\
↓\
用户点击“应用到本地”\
↓\
选择目标路径\
↓\
如果文件已存在，弹出覆盖确认\
↓\
用户确认写入\
↓\
Main Process 执行文件写入\
↓\
Renderer 更新 Artifact 应用状态\
↓\
聊天流显示系统消息\
↓\
Electron 弹出系统通知

### 文件冲突处理

如果目标文件已存在，需要提供：

1. 覆盖
2. 另存为
3. 查看差异
4. 取消

### Artifact 应用状态

Artifact 应用状态包括：

1. notApplied：未应用。
2. applying：正在应用。
3. applied：已应用。
4. conflict：存在冲突。
5. failed：应用失败。

***

## 7.4 Artifact 版本管理

### 功能说明

Artifact 不应只是单一 content，而应该支持版本管理。

推荐结构：

Artifact 表示文件主体。\
ArtifactVersion 表示某一次生成或修改结果。

### Artifact 字段

Artifact 包含：

1. id
2. conversationId
3. title
4. type
5. description
6. currentVersionId
7. latestVersion
8. createdAt
9. updatedAt

### ArtifactVersion 字段

ArtifactVersion 包含：

1. id
2. artifactId
3. version
4. content
5. language
6. changeSummary
7. createdBy
8. createdByType
9. parentVersionId
10. createdAt

### 版本场景

1. CodeAgent 初次生成代码，创建 v1。
2. 用户要求修改，创建 v2。
3. ReviewAgent 提出修改建议，CodeAgent 修复后创建 v3。
4. 用户可以查看历史版本。
5. 用户可以对比 v1 和 v2。
6. 用户可以回滚到某个旧版本。

### PC 端增强

PC 端写入本地文件时，应记录：

1. artifactId
2. versionId
3. targetPath
4. appliedAt
5. applyStatus

## 7.5 系统通知

### 功能说明

系统通知用于增强 PC 端后台体验。

当用户切换到其他窗口时，AgentHub 仍然可以通过系统通知告知任务进度。

### 通知场景

1. Agent 回复完成。
2. 多 Agent 任务完成。
3. Artifact 生成完成。
4. Artifact 写入本地成功。
5. 本地 Agent 启动成功。
6. 本地 Agent 异常退出。
7. 后端连接断开。
8. 长任务失败。

### 通知点击行为

用户点击通知后：

1. 打开 AgentHub 窗口。
2. 切换到对应会话。
3. 高亮对应消息或 Artifact。
4. 如果是文件写入通知，可打开对应 Artifact 详情。

***

### 功能说明

系统托盘用于让 AgentHub 在后台保持运行，并提供快捷入口。

### 托盘菜单

托盘菜单建议包含：

1. 打开 AgentHub
2. 最近工作区
3. 当前 Agent 状态
4. 暂停所有任务
5. 设置
6. 退出

### 托盘状态

托盘图标状态可体现：

1. 空闲
2. Agent 正在工作
3. 有新消息

## 7.7 本地 Agent 进程管理

### 功能说明

PC 端需要预留本地 Agent 进程管理能力。

本地 Agent 可以包括：

1. Local Qwen Agent
2. OpenCode Agent
3. 本地文件工具服务
4. 本地预览服务
5. 本地代码执行服务

### 核心功能

1. 查看本地 Agent 列表。
2. 查看 Agent 运行状态。
3. 启动 Agent。
4. 停止 Agent。
5. 重启 Agent。
6. 查看端口。
7. 查看 PID。
8. 查看日志。
9. 查看最近错误。

### Agent 进程状态

状态包括：

1. stopped
2. starting
3. running
4. stopping
5. error

### 第一阶段实现建议

第一阶段只做 UI 和 Mock 状态。

第二阶段再通过 Electron Main Process 使用 child\_process 启动真实进程。

## 7.8 本地命令执行预留

### 功能说明

本地命令执行用于未来支持 npm install、npm run dev、git diff、测试运行等能力。

### 安全要求

1. 第一阶段不真实执行命令。
2. 后续执行命令前必须展示命令内容。
3. 必须由用户确认。
4. 必须显示执行日志。
5. 必须支持中断。
6. 必须记录执行历史。
7. 高风险命令需要拦截或二次确认。

## 9. 核心交互流程

## 9.1 打开本地项目流程

用户点击“打开工作区”\
↓\
Electron 打开目录选择窗口\

## 13. 验收标准

PC 端第一阶段完成后，应满足：

1. 可以以 Electron 桌面应用形式启动。
2. 主界面复用 Web 端 IM 多 Agent 协作页面。
3. 页面中能看到当前工作区模块。
4. 页面中能看到文件树或文件管理入口。
5. Artifact 面板中有“应用到本地”操作入口。
6. 设置中心中有通知、文件权限、本地 Agent 配置。
7. Agent 联系人中可以区分本地 Agent 和云端 Agent。
8. 可以展示本地 Agent 运行状态。
9. 可以模拟系统通知。
10. 不破坏原有 Web 端功能。
11. 不为 PC 端重写一套独立 UI。
12. 多端能力通过 Platform Adapter 隔离。
13. Electron 本地能力通过 preload 和 IPC 暴露，不直接在 Renderer 中使用 Node.js API。

***

## 14. 总结

AgentHub PC 端的核心价值是让多 Agent 协作真正进入本地开发环境。

Web 端解决的是：

用户如何与 Agent 聊天、协作、查看产物。

PC 端解决的是：

Agent 如何与用户的本地项目、本地文件、本地工具和系统能力连接。

因此，PC 端不应该推翻 Web 端，而应该在 Web 端基础上通过 Electron 增加本地增强能力。

最终目标是形成：

一套 React 业务 UI\
一套统一 API 与消息模型\
一套 Platform Adapter\
一套 Electron IPC 本地能力层

这样既能保持多端统一，又能满足 PC 端本地文件交互、系统通知和 Agent 进程管理的要求。
